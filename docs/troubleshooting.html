Troubleshooting

Common issues encountered while configuring, running, or contributing to the Patrol Field Effort Workflow, and how to resolve them. If your issue isn't listed here, open an issue on GitHub.

Configuration & EarthRanger Connection

Workflow run fails instead of returning an empty dashboard

get_patrol_observations is configured with raise_on_empty: true and restricted to status: ["done"]. If no completed patrols fall within the selected time range and area of interest, the run raises an error rather than producing a dashboard with empty maps. Widen the time range or double-check the area-of-interest selection first.

No "grouper" option appears in the configuration form

This is expected — groupers are fixed to an empty list (partial: groupers: []) for this workflow. Every metric and the operational days table are always computed for the combined dataset; there is no per-patrol-type or per-ranger map/table variant.

Can't find the auto-scale vs. custom grid option

This workflow overrides the create_geo_meshgrid schema so only the custom cell size path is available — the auto/custom toggle is hidden by an RJSF ui:widget: hidden override and fixed to "Customize". Only the Grid Cell Size field (metres, default 1000) is exposed.

Maps & Metrics

A map is almost entirely grey ("Unvisited")

Grey (#808080) marks cells with no recorded value for that metric — no patrol trajectory intersected the cell (days-since-visit / dwell time) or no route coverage was computed there (linear time density). This is expected for a large study area with sparse patrol coverage, or a narrow time range. It does not indicate an error.

All coloured cells show the same bin / colour

Each metric is classified into 5 natural-breaks (Jenks) bins. With very few visited cells or little variation in the underlying values, natural breaks can degenerate to fewer effective classes — this is a property of the classification scheme, not a workflow bug.

Linear Time Density map looks inconsistent with the other two maps for unvisited cells

calculate_linear_time_density only returns cells that a patrol trajectory actually intersects. Grid cells with zero coverage are recovered separately via a difference overlay against the full clipped grid and concatenated back in, so every cell appears in the final map. If this reconciliation step is modified, unvisited cells can silently disappear from the linear time density map while still appearing on the other two.

Distance, area, or dwell-time figures look slightly off at high latitudes

All grid construction and the three field-effort metrics are computed in EPSG:3857 (Web Mercator), which distorts area and distance increasingly with distance from the equator. For most East African study areas this is a minor effect, but it's worth keeping in mind when comparing patrol coverage percentages across sites at very different latitudes.

Contributing & CI

These apply if you're modifying the workflow itself (spec.yaml or the generated workflow directory) and opening a pull request.

Error: test-cases.yaml not found at test-cases.yaml

This repository currently does not have a test-cases.yaml file, but .github/workflows/test.yml requires one with at least one top-level test case before it will validate or test the workflow. Add a test-cases.yaml with at least one entry (<case-name>: params: {...}) before opening a PR — see a sibling workflow such as mnc-patrol-effort/test-cases.yaml for the expected format.

Found wildcard version (*) in requirements or Found local file channel (file://) in requirements

Every dependency under requirements in spec.yaml must pin an exact version (or range) and use a remote conda channel — wildcard versions and local file:// channels are only valid for local development, not for CI using published packages.

VERSION.yaml (...) must be greater than main branch (...)

Bump MAJ/MIN/PATCH in the generated workflow directory's VERSION.yaml so it's strictly greater than the version on main before opening or updating a PR.

Generated workflow directory differs from spec.yaml

Run the recompile script locally and commit the result:

pixi run --manifest-path pixi.toml --locked bash -c "./dev/recompile.sh --update"

No outputs written / can't find results

All outputs are written to the directory specified by the ECOSCOPE_WORKFLOWS_RESULTS environment variable. Confirm it's set and points to a directory the workflow process can write to.
